<!-- Raw HTML blocks. The site splices; the formatter keeps the bytes. -->

# Blocks that splice cleanly

A void element on its own line, which is a complete element with no end tag:

<img src="diagram.png" alt="A diagram" width="640">

A balanced block over several lines, with interior indentation prettier does not
touch:

<figure class="wide">
  <img src="chart.png" alt="A chart">
  <figcaption>Revenue, by quarter</figcaption>
</figure>

Attribute spelling prettier leaves exactly as written, and so do we:

<div    class="loose"   id="spaced"  data-kept>text</div>

A block a container holds still splices: the item's indentation and the quote
marker stay outside the region's extent.

- <div class="listed">a block in a list item</div>
- plain item

> <div class="quoted">quoted block</div>

# Blocks that do not splice

The wrapper idiom splits one element across two blocks. The opener carries an
attribute, so tree-sitter-html accepts it as a complete element and it splices;
the closer is an ERROR and stays with the host. Nothing notices that the two
belong together, which is why `format = false`:

<div class="wrapper">

Markdown **inside** the wrapper stays markdown.

</div>

A bare opener carries no attribute, so it is an ERROR on its own and both halves
stay with the host:

<section>

Still inside.

</section>

# What never reaches the site

An inline tag on its own line is a paragraph, not an `html_block`, so the site
never sees it and the markdown package emits it verbatim as before:

<span class="badge">inline</span>

Quoting a block needs the blank line above it: a `>` continuation directly after
an open html block is an ERROR in the block grammar, so the corpus cannot write
that form at all.
